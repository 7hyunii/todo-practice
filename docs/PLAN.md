# 기능 설계 계획

## 1. 목표 기능

- 할 일 등록
- 할 일 목록 전체 조회
- 할 일 개별 조회
- 할 일 수정
- 할 일 완료 상태 변경
- 할 일 삭제

## 2. 기능별 규칙

### 기능명: 1. 할 일 등록
| 항목                  | 내용                                                                                             |
|-----------------------|--------------------------------------------------------------------------------------------------|
| 정상 동작             | 할 일 등록                                                                                       |
| 입력값                | 제목(title), 설명(description)                                                                   |
| 제한 조건             | 제목은 필수, 공백만 입력할 수 없고 최대 30자, 설명은 최대 1,000자                                                     |
| 기본값                | 설명을 생략하면 "", 완료 상태는 false                                                            |
| 실패 조건과 처리 방법 | - 제목이 없거나 공백뿐이거나 30자를 초과하면 입력 오류<br> - 설명이 1,000자를 초과하면 입력 오류 |

### 기능명: 2. 할 일 목록 전체 조회

| 항목                  | 내용                                  |
|-----------------------|---------------------------------------|
| 정상 동작             | 모든 할 일을 ID 오름차순으로 반환     |
| 입력값                | X                                     |
| 제한 조건             | X                                     |
| 기본값                | X                                     |
| 실패 조건과 처리 방법 | 조회 결과가 없으면 빈 목록 반환(정상) |

### 기능명: 4. 할 일 수정

| 항목                  | 내용                                                                                                                                                             |
|-----------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 정상 동작             | - 개별 조회로 기존 제목과 설명을 불러와 수정 화면에 표시<br>- 저장하면 화면의 제목과 설명으로 기존 데이터를 변경<br>- 완료 상태는 변경하지 않고 유지 (별도 기능) |
| 입력값                | id, 제목(title), 설명(description)                                                                                                                               |
| 제한 조건             | - 제목과 설명은 등록 규칙과 동일<br>- 설명을 생략하면 빈 문자열로 저장                                                                                                  |
| 기본값                | 수정 화면 초기값은 기존에 저장된 제목과 설명                                                                                                                     |
| 실패 조건과 처리 방법 | - 해당 ID가 없으면 찾을 수 없음 오류<br>- 제목과 설명 규칙을 위반하면 입력 오류                                                                                         |

## 3. 데이터 모델

### 모델명: Todo

| 필드        | 타입    | 의미      | 제약 조건 / 기본값                 |
|-------------|---------|-----------|------------------------------------|
| id          | Long    | 식별자    | 기본 키, 자동 증가                 |
| title       | String  | 제목      | 필수, 공백만 입력 불가, 최대 30자  |
| description | String  | 설명      | 생략 가능, 생략 시 "", 최대 1000자 |
| completed   | boolean | 완료 여부 | 기본값 false                       |

## 5. 코드 구조와 책임

- 패키지 구성 방식: 계층형
- 패키지 / 파일 구성:
  ```tree
  todopractice/
  ├── controller/
  │   └── TodoApiController.java
  ├── service/
  │   └── TodoService.java
  ├── repository/
  │   └── TodoRepository.java
  ├── domain/
  │   └── Todo.java
  └── dto/
      ├── TodoSaveRequest.java
      └── TodoResponse.java
  ```

| 구성 요소  | 담당할 책임                                                           |
|------------|-----------------------------------------------------------------------|
| Controller | HTTP 요청 수신, 요청 입력값 검증, Service 호출, 상태 코드와 응답 반환 |
| Service    | 할 일 등록·조회·수정·상태 변경·삭제 기능 처리                         |
| Repository | DB 저장•조회•삭제                                                     |
| Domain     | Todo 엔티티(데이터 구조•동작) 정의                                    |
| DTO        | 요청·응답 데이터 구조 정의, 요청 검증 조건 선언                       |
